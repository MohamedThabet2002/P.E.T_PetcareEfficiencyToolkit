# Changelog

## [2.0.0-beta1] - 2026-10-11

### Added
- **Safety Backup Before Database Upgrades**: The first launch of a newer build over an existing database now writes an automatic backup *before* any schema migration runs. If an upgrade fails, the previous database is recoverable from the Backups folder. A fresh install (no database file yet) takes no backup.
- **Receipt Print & Client Copy**: The Receipt Details dialog now offers **Print** and **Print for Client** for the receipt card (clinic name, item lines, totals). The client copy leaves out the payment details — exactly like the receipt in the Add Visit wizard — and is only printed for fully paid receipts; an unsettled receipt shows a message saying only fully paid receipts are printed to clients. The dialog also announces money changes through a `data_changed` signal so the Receipts ledger, the Visits page and the Dashboard refresh as soon as a payment or edit lands.
- **Payments In The Audit Log**: Adding, editing or deleting a payment is now written to Reports → Audit Log with the acting user, and payment amounts are validated (zero/negative amounts are refused).
- **Receipt Editing Tests**: New coverage for the receipt dialogs and payment statuses (`Partial`, zero-total receipts, delete-with-payments).
- **One Excel Workbook In, One Out**: **Export Excel Data** now writes a **single `.xlsx` workbook** with one sheet per data type (`Owners`, `Pets`, `Supplies`, `Visits`) plus the `Instructions` sheet, instead of four separate files, and the import dialog reads that workbook back **sheet by sheet** - the **Import every data sheet in this workbook** option is offered and pre-selected when a workbook holds several data types. Each sheet is matched by its columns, so sheet names and order do not matter; the sheets are imported owners → pets → supplies → visits in one pass with a shared owner/pet cache, an owner added by one sheet is found (never duplicated) by the next, the preview lists every sheet with its data type and row count, and the results name the sheet a failed row came from. CSV export is unchanged (one file per data type).
- **Live Batch Updates**: Adding, editing or deleting a stock batch now refreshes the Supplies page immediately, so the quantity column always shows the current batch total without reopening the Stock Batches dialog or reloading the page.
- **Per-Batch Expiry & Buy Price**: Every stock batch now stores its own expiry date and buy price (new `stocks.expiry_date` / `stocks.buy_price` columns, migration `021`, existing batches inherit the item's values). The Add/Edit Batch dialogs gained **Expiry Date** and **Buy Price** directly under Purchase Date, the batch table lists both columns, and clicking a batch number opens that batch's own details (Batch ID, batch quantity, its dates, price, supplier and notes) instead of the item-wide values.
- **Excel / CSV Import**: Import owners, pets, supplies and visits into the database from the Settings page (`Database Backup` tab → `Import Data`). Pick a `.xlsx`/`.csv` file, review the auto-mapped columns in a preview, run a **Validate** dry run, then import. Existing records are skipped rather than overwritten, invalid rows are reported with their file row numbers, a safety backup is created first, and starter templates can be saved per data type.
- **Starter Templates**: The Import Data section on the Settings page now separates the import action from the templates: the **Import from Excel or CSV** button is the filled primary action, and a **Starter Templates** block below it offers **Save Excel Templates (.xlsx)** and **Save CSV Templates (.csv)** with a short caption. The import dialog's **Save Template...** defaults to an `.xlsx` file with the Excel filter selected. CSV remains available for both actions.
- **Excel / CSV Export**: Export your current data from the Settings page (`Database Backup` tab → **Export Data**) with **Export Excel Data (.xlsx)** or **Export CSV Data (.csv)**, which writes one file per data type (owners, pets, supplies, visits) into a folder of your choice and reports how many records each file holds. The exported files use **exactly the import-template columns** - same headers, same hover examples, same Instructions sheet - so you can open one, change or add what you need, and import it straight back. The import dialog also grew an **Export Data...** button that exports just the data type selected in the drop-down. Owners, pets and visits are skipped as duplicates on re-import, matching the existing import behaviour.
- **No Sample Rows in Templates**: Starter templates now contain headers only, so an untouched file can never add a demo owner, pet, item or visit to your database. The Excel template keeps the guidance where it cannot be imported: hovering any header shows whether the column is required plus an example value and a note about the expected format, and a second **Instructions** sheet walks through the steps and lists every column with an example. The import dialog refuses that sheet — switching to it disables Validate and Import and explains why.
- **Doctor Attribution**: Linked user accounts to doctors and tracked doctors on visits, appointments, and follow-ups, including authorized substitute-doctor assignment.
- **Clinical Exam Accordion Cards**: The five clinical sections on the Add Visit wizard's Clinical Exam step (Health Stats, Tests, Treatments, Vaccinations and Medications) now read as a list of titled accordion cards instead of bare checkboxes. Every card carries a chevron that flips open when you expand it, a live right-aligned summary (**None** / **1 recorded** / **2 selected** / ...) so a collapsed section still says what it holds, and a brand-tinted hover state; an expanded card shows only its own rows, so a closed card is exactly one line tall. The consultation charge sits in a matching one-line **Consultation** card above them instead of a loose form row.
- **Percentage Discount On The Add Visit Bill**: The Billing & Review step of the Add Visit wizard now has a **Discount** bar at the bottom of the page, under the receipt, entered as a percentage exactly like the Edit Receipt dialog (0–100 %) with a live **Total After Discount** beside it. The receipt still prints the money the percentage works out to, and that cash discount is what the visit is saved with.
- **Percentage Discount On Quick Purchase & Add Supplies**: The **Quick Purchase** dialog and the **Add Supplies** (Bulk Purchase) dialog now carry the same **Discount** percentage bar as the Add Visit bill. The cash discount is stored in `receipts.discount` and taken off the receipt total: Quick Purchase records its full payment against the discounted figure, and a bulk purchase folds the discount into the single shared expense receipt once all items are recorded.
- **Amount Paid Entered At The Counter**: All three billing dialogs — Quick Purchase, Add Supplies
  (Bulk Purchase) and now **Add Visit** — ask for the **Amount Paid** right next to the discount and
  total. It defaults to the full (discounted) total, and whichever figure you type is recorded as an
  instant payment — no trip to the Receipts page afterwards. Each dialog also carries a **Payment
  Method** selector (Cash / Card / Bank Transfer / Other, matching the Receipt Info add-payment
  dialog), so the instant payment is tagged with how it was handed over. A purchase/visit that only
  receives part of the bill lands **Partial**, nothing handed over leaves it **Unpaid**, and a bulk
  purchase logs the money against its shared expense receipt the same way.
- **Appointment Dialog**: Added a full appointments dialog from the Dashboard `View all` action.
- **Refunds For Overpaid Receipts**: When a batch correction shrinks a bill that was already settled, the extra money is now visible and returnable.
 The Receipt Details dialog shows `Paid: … | Credit: …` with a **Record Refund** button instead of **Add Payment**, and the Dashboard's Remainders table lists the receipt under **Refund Due** until the credit is handed back (an expense the clinic has not paid at all appears beside it as **Expense Unpaid**). A refund is stored as a negative payment, so partial refunds are possible and the receipt settles only when the credit is gone.
- **Batch Corrections Show In The Receipt**: Correcting or deleting a stock batch now adds a revision to the **Adjustments** list of the receipt it was bought on - who changed it, the quantity before and after, and the signed money difference - writes an `ADJUST` entry to the Audit Log, and re-settles the receipt's `Paid / Partial / Unpaid` status. A bill that halves after its purchase was corrected to the real quantity no longer claims it is fully paid, and its overpayment surfaces as the refund above.
- **Receipt ID On Every Batch**: The Stock Batches dialog gained a **Receipt ID** column linking each batch to the expense receipt it was bought on; clicking it opens that receipt's details. Batches with no linked receipt (for example ones created before the link existed) show an empty cell.
- **Configurable Auto-Cancel Window**: Settings → Clinic Profile → **Scheduling Rules** now holds **Auto-cancel after** (1–720 hours, default 24), which decides how long an appointment or follow-up stays **Late** before it is auto-canceled. A live example line under the field spells the rule out ("a visit at ... turns Late at that time and is auto-canceled after ..."), and the new value applies immediately - no restart.
- **Reports Views**: Added category-specific Overview, Financial, Patient, Supply, and Audit report views with category-aware printing.
- **Dashboard Quick Purchase & Wide-Window Buttons**: The Dashboard now has all three action buttons — **Add Visit**, **Add Supplies** and **Quick Purchase** (the Quick Purchase button is back, opening the same dialog as the Visits page). Every button follows its permission, and when a user is allowed all three, the role's two main buttons always show while the third only appears once the window is wider than 1200 px — the same threshold as the next-client countdown: admins get **Quick Purchase** held back, doctors and other users get **Add Supplies** held back. The permission descriptions in User Management (Change Permissions / Customize Roles) spell the rule out in both languages.

### Changed
- **Pre-Release Versioning**: The app version is now `2.0.0-beta1` (single source `src/config/meta.py`, passed to the installer by `package_app.py`), so testers can tell a beta apart from the final release and upgrades flow `1.0.0 → 2.0.0-beta1 → 2.0.0-beta2 → 2.0.0`.
- **Consistent Money Formatting**: Every receipt-facing screen (Edit Receipt, Visit Adjust, the receipt previews and the ledger) now formats money the same way (`$ 1,234.56`), including signed deltas (`+ $ 5.00` / `- $ 5.00`); the `€` on the adjustment previews and ledger was the outlier.
- **Ledger Columns Match Their Filters**: The Receipts ledger's **Total Price** column now shows the receipt total (what filtering on *total price* searches) instead of the line total, every filter value follows the column rather than its translated label, and the row's per-line total is exposed separately as `line_total`.
- **Theme-Driven Status Colors**: The Paid/Partial/Unpaid strip and the adjustment delta colors in the Receipt Details dialog come from the palette (`state_success` / `state_warning` / `state_danger`) instead of hard-coded hex, so they follow light/dark themes.
- **Discounts Round To The Cent**: The discount preview and the discount actually saved are now the same number (33.33% of 30.00 stores 10.00, not 9.999), on both the Edit Receipt and Visit Adjust dialogs and in the Visit Details save path.
- **Single Adjustment Trail**: Editing a receipt from the Receipt Details dialog and adjusting it from the Visit Details dialog now write the same revision row + `ADJUST` audit entry with the same wording, so the Adjustments list reads consistently whoever made the change.
- **Next Client Rolls On At Appointment Time**: The Dashboard's **Next Client Scheduled in** widget no longer freezes at `00:00:00` - the moment the current appointment's time arrives it re-reads the schedule and counts down to the following client (and clears itself when nothing is left), instead of waiting for some other refresh. The appointments table below it is rebuilt at the same moment, so a row that just turned **Late** moves into place.
- **Four Appointment Rows**: Today's Appointments now shows four rows - the latest completed appointment, the overdue (**Late**) appointment closest to being auto-canceled, and the two soonest pending appointments. Missing categories are skipped instead of leaving an empty row.
- **Late Items Stay Visible**: The Dashboard's appointment panel now lists overdue (**Late**) appointments and follow-ups instead of hiding them - they are painted orange, sorted first, and listed once. The Appointments tab also finds them when you type `Late` in the status search, which was impossible before because the status is derived when it is read and never stored.
- **Add Visit Vertical Space**: The Add Visit dialog no longer paints tall, empty boxes. Each step now keeps its spare height at the bottom of the page instead of stretching its content, so the supplies list no longer renders as a huge empty panel and the receipt preview is the size of a receipt. The Clinical Exam step's five sections (Health Stats, Tests, Treatments, Vaccinations, Medications) now genuinely collapse when unticked - previously they only greyed out while keeping every row visible, which made that step about four screens tall. The dialog also sizes itself to its tallest step rather than sitting at a fixed height, so the band of dead space underneath the content is gone, and the optional follow-up booking moved inside the Visit Details card so step 1 is a single row of two cards.
- **Add Visit Wizard Redesign**: The Add Visit dialog is now a compact four-step wizard with a clearer sense of progress. The step indicator at the top shows numbered badges that fill in as you advance, greys out the steps still to come, adds a `Step 2 of 4` counter, and lets you click back to any step you have already reached (never forward past a step whose details are still required). The first step is now two titled cards side by side - **Client & Pet Details** next to **Visit Details** - replacing the long single scrolling column. The dialog is wider (900px) with a minimum size so it can no longer be squeezed unreadably, the footer gained a hairline divider and evenly sized buttons, and every field got a placeholder, the visit date now shows a real date *and time*, and the weight field is marked `kg`.
- **Receipt Preview**: The Billing & Review step now labels its printable receipt, includes a one-line hint about printing or exporting a copy for the owner, tightens its spacing and adds a rule above the totals. **Print** and **Export PDF** are now secondary (outlined) buttons so **Save Visit** is the only filled primary action on the screen.
- **Supplies & Packages Rows**: The row delete buttons on the supplies and service packages lists are now pinned to the right edge in line with their column headers, and both lists use the same compact section heading as the rest of the wizard.
- **Supplies Quantity Column**: The Supplies page now shows an item's quantity as the total across its stock batches (matching the Stock Batches dialog) instead of the live stock, and the low/out-of-stock row highlighting follows the same number. The live stock is still what stock checks, restocks and reports use.
- **Edit Supply Dialog**: The item edit dialog on the Supplies page no longer has a Buy Price field — the price belongs to each stock batch and is edited from the Stock Batches dialog.
- **Admin Page Layout**: The Admin page is now tabbed, with one tool per tab (`User Management` and `Restore Records`). The tools open inline instead of as separate dialogs, each table fills the tab with its action buttons pinned to the bottom, and a global **Save / Cancel** row sits at the bottom of the page like the Settings page.
- **Clinical Navigation**: Clients now contains Clients and Pets, while Visits contains Visits and Appointments.
- **Dashboard Actions**: Dashboard Add Visit and Quick Purchase now use the same dialogs as the Visits page.
- **Appointment Services**: Selected appointment services are now persisted and displayed.

### Fixed
- **Upgrading Between Pre-Releases And The Final Release**: The installer's upgrade check now compares versions semantically (dotted numbers plus a `beta`/`rc` suffix) instead of as plain text. As strings, `'2.0.0-beta2' >= '2.0.0-beta1'` and `'2.0.0-beta1' >= '2.0.0'` are both true, so beta2 was refused over beta1 and the final release was refused over a beta. The order is now `1.0.0 < 2.0.0-beta1 < 2.0.0-beta2 < 2.0.0`.
- **Upgraded Visits Schema Keeps Its Views**: Rebuilding `visits` to drop the stale `client_id` column now drops *every* dependent view (including the previously missed `v_pet_health_timeline`) before the swap and recreates them afterwards, so an upgrade no longer leaves the rebuild silently rolled back with billing/home-record views missing until the next launch.
- **Receipt Edits Delete The Exact Line**: Editing a receipt now targets the specific supply/package line PK when removing a line, so deleting one of two identical lines restores only that line's stock instead of every line with the same item and the wrong quantity.
- **Receipt Edits Keep Their Payments Consistent**: Editing a receipt now recomputes its `Paid / Partial / Unpaid` status from the payments recorded against it, so lowering a settled receipt or changing its lines can no longer leave a stale status and an out-of-date balance.
- **Expense Lines Survive A Receipt Edit**: Expense and Quick Purchase `Other` lines are now saved with a quantity and unit price (backfilled by migration `024_receipt_other_unit_price`), so editing a receipt no longer zeroes them out of the ledger.
- **Quick Purchase Records Fully Or Not At All**: A failed payment insert can no longer commit a receipt marked `Paid`, and a failed expense/purchase insert now rolls back instead of leaving a half-written receipt - the dialogs report the real reason instead of a generic failure.
- **Deleting A Receipt Gives Stock Back**: Removing a sale re-adds its quantities to the item's live stock **and** its stock batches (oldest-first purchase history preserved) and logs a `sale_return` movement; its payments go with it via the foreign key, and restoring the delete from Restore Records performs the mirror.
- **No More Orphaned Receipt Lines**: Line items whose supply, service or package row has since been removed are kept in the receipt (labelled "deleted item/service/package") instead of silently vanishing from the edit dialog and the receipt card.
- **All Receipt Queries Finish Before Commit**: Queries that stayed active while a transaction committed ("cannot commit transaction - SQL statements in progress") are now closed first, across payments, receipt edits, consultation reconciliation and subtotals.
- **Repeated Pet Rows**: Importing a pet whose owner was added by an earlier sheet failed with `Pet not found ... Import pets first`, and two rows for the same pet created it twice. The import now remembers every pet and item it adds, so a later sheet of the same run finds them.
- **Batches Now Deplete With Sales**: Selling supplies (visit supplies or Quick Purchase) took units out of the item's stock but left every batch untouched, so the batch total drifted away from the real stock and the quantity shown on the Supplies page stayed frozen. Batches are now drawn down oldest-purchase-first, a fully used batch keeps its row at `0` so the purchase history survives, and editing a receipt that removes or enlarges a supply line puts the units back into the newest batch. `batch_quantity` and `current_stock` therefore stay in step.
- **Batch Changes Stay In Sync And Leave A Trail**: Adding, editing or deleting a stock batch only ever changed the batches themselves, so the item's live stock - the number used for stock checks when selling and shown on the Supplies page - went stale until something else touched the item, the stock movement log never heard about it, and correcting a batch's quantity had no effect on the profit reports at all. Every batch change now recomputes the item's stock from its batches (which also repairs an item that had drifted earlier instead of carrying the error forward), writes a signed row in the stock movement ledger, and posts the financial effect of the difference as an expense receipt - so a batch logged as 100 and corrected to 10 nets out to the real 10. Each change is also written to the Audit Log as a **stock batch** entry credited to the user who made it. Selling through Quick Purchase or by editing a receipt now logs its movement too (previously only visits did), and the purchase recorded with an item now appears in the ledger instead of the log starting at the item's first sale.
- **Batch Corrections Amend One Receipt**: Correcting a batch's quantity, or deleting the batch, created a brand-new expense receipt every time, so one purchase that was adjusted twice appeared in the ledger as three separate costs and the profit reports read it as three buys. A batch now remembers the receipt it was bought on, and every correction is folded into that same entry - buying 20 and correcting it to 10 leaves a single line worth 10, and deleting the batch takes it back to zero. If the purchase receipt has since been removed from the ledger, the correction is posted on its own rather than lost, and batches created before this change simply keep working as before.
- **Follow-up Statuses**: Follow-ups now use exactly `Pending`, `Completed` and `Canceled`. The All Appointments dialog and the follow-up editor offer all three and save the chosen status instead of silently keeping `Scheduled`; the retired `Scheduled` and `Missed` statuses are backfilled as `Pending` and pruned by migration `020_followup_status_prune` (added by `019_followup_status_states`).
- **Follow-up Editing**: Double-clicking a follow-up row on the Appointments tab now opens the follow-up editor and saves to the follow-up record. Previously the row was treated as an appointment, so the edit either did nothing or wrote to the wrong record when a follow-up and an appointment shared the same id.
- **Payment Buttons No Longer Pile Up**: Re-rendering the Receipt Details dialog rebuilt its Payments toolbar without removing the previous one, so adding, editing or deleting a payment (or recording a refund) left the old buttons stacked over the new ones.

## [2.0.0-beta1] - 2025-01-01

### Added
- **Settings Page**: Replaced the old settings dialog with a fully self-contained tabbed settings page.
- **Inventory Reorder Tab**: New dedicated tab for managing inventory reorder levels (placed before the DEV tab).
- **Custom Palette Editor**: Moved custom palette editing from DEV to Appearance tab, shown only when Custom theme is selected.

### Changed
- **Consultation Fee Migration**: Consultation fee is now stored in `settings.json` under the `consultation_fee` key (single source of truth), replacing the old `SETTING_CONSULT_FEE_LABEL` constant.
- **Settings Page Layout**: Improved tab order (Clinic Profile, Appearance, Database Backup, Suppliers, Custom Lists, Inventory Reorder, DEV) and page-level Save/Cancel buttons.
- **User Management**: Admin-only gating for the Manage Users button.

### Fixed
- **Corrupted Error Message**: Fixed a corrupted error message in `main.py` that displayed garbled text.
- **Database.db in .gitignore**: Added `Database.db` to `.gitignore` to prevent committing local database data.
- **requirements.txt Encoding**: Converted `requirements.txt` to UTF-8 encoding to prevent `pip install -r requirements.txt` failures.

## [1.0.0] - 2024-05-15

### Added
- **Initial Release**: Complete veterinary clinic management system.
- **Patient Management**: Centralized database for owners and pets with visit history tracking.
- **Inventory Management**: Automated stock tracking, reorder levels, and bulk purchase tools.
- **Financial Module**: Support for service receipts, product sales, and expense logging.
- **Dashboard Analytics**: Real-time visualization of revenue, visits, and stock trends.
- **Localization**: Full support for English and Arabic (Right-to-Left) languages.
- **UI/UX**: Dynamic Dark Mode support and DPI-aware scaling for high-resolution monitors.
- **Data Protection**: Automatic 7-day rolling database backups and manual backup tools.
- **Packaging**: Automated build scripts using PyInstaller and Inno Setup.
